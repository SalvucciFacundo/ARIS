# Specification: ComfyUI Workflow JSON Export & Metadata Interoperability

## Purpose
Define the functional and interface specifications for embedding, inspecting, and exporting generation metadata and ComfyUI workflow graphs in PNG images generated or managed by ARIS. This enables seamless drag-and-drop interoperability with ComfyUI, universal metadata tracking across generation backends, and command-line inspection and extraction.

---

## Requirements

### Requirement: REQ-WORKFLOW-1: PNG Chunk Metadata Injection
The system MUST provide pure-Go utility functions to inject custom metadata `tEXt` chunks into standard PNG byte streams prior to the `IEND` chunk while recalculating and embedding valid IEEE CRC-32 checksums.

#### Scenario: Successful injection of ComfyUI metadata into PNG byte stream
- **GIVEN** a valid PNG image byte buffer with standard 8-byte signature (`\x89PNG\r\n\x1a\n`) and valid `IHDR`, `IDAT`, and `IEND` chunks
- **WHEN** metadata key-value pairs (e.g., `prompt`, `workflow`, `parameters`) are injected via `pkg/imgutil/pngmeta.go`
- **THEN** the resulting byte stream MUST contain valid `tEXt` chunks placed immediately before `IEND`
- **AND** each injected `tEXt` chunk MUST contain a 4-byte chunk length, 4-byte chunk type (`tEXt`), null-separated keyword and text string, and an IEEE CRC-32 checksum computed over the chunk type and chunk data bytes
- **AND** the original image pixels and structure MUST remain intact and readable by standard PNG image decoders.

#### Scenario: Multi-chunk injection with distinct keywords
- **GIVEN** a generated image with both execution graph (`prompt`) and UI node graph (`workflow`)
- **WHEN** `InjectMetadata` is called with multiple key-value pairs
- **THEN** distinct `tEXt` chunks MUST be written for each keyword in order
- **AND** every chunk MUST have its own independent length and CRC-32 checksum.

### Requirement: REQ-WORKFLOW-2: ComfyUI Drag & Drop Interoperability
Images generated via the ARIS ComfyUI adapter MUST embed metadata in the exact format and keys expected by the ComfyUI web client (`prompt` and `workflow` JSON strings).

#### Scenario: ComfyUI loads node graph from ARIS-generated image
- **GIVEN** an image generated by ARIS using the ComfyUI adapter with an active workflow graph
- **WHEN** the saved PNG file is loaded or dragged into the ComfyUI web canvas
- **THEN** ComfyUI MUST parse the `workflow` and `prompt` `tEXt` chunks without error
- **AND** the ComfyUI UI canvas MUST reconstruct the full node topology, node connections, inputs, and widget parameters.

---

### Requirement: REQ-WORKFLOW-3: PNG Chunk Reading & Extraction
The system MUST provide functionality to scan PNG chunk sequences, identify `tEXt` (and optionally `iTXt`) metadata chunks, and extract all key-value pairs without decoding the underlying image raster data.

#### Scenario: Extract all metadata key-value pairs from PNG
- **GIVEN** a PNG file containing embedded `prompt`, `workflow`, and `parameters` `tEXt` chunks
- **WHEN** `ExtractMetadata` or `ReadChunks` is executed on the PNG file stream
- **THEN** the reader MUST parse chunk headers and return a map of extracted keywords and their corresponding string values
- **AND** the reader MUST validate chunk CRC-32 checksums during iteration
- **AND** the operation MUST NOT load uncompressed image raster pixels into memory.

---

### Requirement: REQ-WORKFLOW-4: CLI Workflow Inspection (`aris workflow inspect`)
The system MUST provide a CLI subcommand `aris workflow inspect <image.png>` to display human-readable summaries or machine-readable JSON metadata from target PNG files.

#### Scenario: Inspect workflow with default human-readable output
- **GIVEN** an image containing ComfyUI workflow metadata
- **WHEN** a user executes `aris workflow inspect <image.png>`
- **THEN** the command MUST exit with code 0
- **AND** the CLI MUST display a formatted table or summary containing generation backend, prompt details, node count, and model parameters.

#### Scenario: Inspect workflow with `--json` output flag
- **GIVEN** an image containing embedded metadata
- **WHEN** a user executes `aris workflow inspect <image.png> --json`
- **THEN** the command MUST output valid JSON to stdout containing all extracted metadata key-value pairs (including parsed `prompt` and `workflow` objects when present)
- **AND** the output MUST be valid for consumption by JSON processors such as `jq`.

---

### Requirement: REQ-WORKFLOW-5: CLI Workflow Export (`aris workflow export`)
The system MUST provide a CLI subcommand `aris workflow export <image.png> [-o <path>]` to extract the workflow graph JSON and save it to disk or stdout with overwrite protection.

#### Scenario: Export workflow to default output file
- **GIVEN** a PNG image `render.png` containing a `workflow` metadata chunk
- **WHEN** a user runs `aris workflow export render.png` without the `-o` flag
- **THEN** the command MUST extract the `workflow` JSON payload and write it to `render.workflow.json`
- **AND** the command MUST print a confirmation message indicating the destination file path.

#### Scenario: Overwrite protection when destination file exists
- **GIVEN** a target export file `output.json` that already exists on disk
- **WHEN** a user executes `aris workflow export render.png -o output.json` without `--force`
- **THEN** the command MUST fail with a non-zero exit code
- **AND** the CLI MUST output an error stating that the file exists and suggest passing `--force` (`-f`).

#### Scenario: Forced overwrite with `--force` flag
- **GIVEN** a target export file `output.json` that already exists on disk
- **WHEN** a user executes `aris workflow export render.png -o output.json --force`
- **THEN** the command MUST overwrite `output.json` with the extracted workflow JSON and exit with code 0.

#### Scenario: Export to stdout using `-o -`
- **GIVEN** an image containing ComfyUI metadata
- **WHEN** a user executes `aris workflow export render.png -o -`
- **THEN** the raw workflow JSON MUST be printed directly to stdout without auxiliary log messages.

---

### Requirement: REQ-WORKFLOW-6: Multi-Backend Metadata Embedding
The system MUST embed standard generation metadata into PNG outputs across all generation backends (ComfyUI, Fal.ai, Pollinations, OpenAI DALL-E) under the `parameters` `tEXt` chunk for cross-platform reproducibility.

#### Scenario: Embedding parameters for non-ComfyUI backends
- **GIVEN** an image generated via Fal.ai, Pollinations, or OpenAI
- **WHEN** the image is saved to disk
- **THEN** the system MUST inject a `parameters` `tEXt` chunk containing generation prompt, model name, seed, aspect ratio, steps, and CFG scale
- **AND** the embedded parameters MUST adhere to standard A1111/Civitai/ARIS metadata format.

---

### Requirement: REQ-WORKFLOW-7: Robust Error Handling & Corrupted Input Rejection
The system MUST detect and reject invalid file formats, corrupted chunk headers, and invalid checksums without crashing or panicking.

#### Scenario: Non-PNG file inspection
- **GIVEN** a JPEG, WebP, or arbitrary non-PNG file passed to inspection or extraction
- **WHEN** the system attempts to process the file
- **THEN** the system MUST return `ErrInvalidPNGSignature`
- **AND** the CLI MUST report a clear error message indicating that the file is not a valid PNG.

#### Scenario: PNG without metadata chunks
- **GIVEN** a valid PNG image that contains no `tEXt` or `iTXt` metadata chunks
- **WHEN** `aris workflow inspect` or `aris workflow export` is run
- **THEN** `inspect` MUST notify the user that no workflow or generation metadata was found
- **AND** `export` MUST exit with an error code and message stating no exportable workflow was detected.

#### Scenario: Corrupted chunk CRC
- **GIVEN** a PNG image with a tampered or corrupted CRC-32 checksum in a metadata chunk
- **WHEN** the chunk reader parses the stream
- **THEN** the system MUST detect the checksum mismatch and return `ErrInvalidChunkCRC` with the expected and actual CRC values.
